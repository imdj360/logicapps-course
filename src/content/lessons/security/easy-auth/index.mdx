<Step id="problem" name="A URL is a password" tag="PROBLEM">
A Request trigger's callback URL carries a **Shared Access Signature** (SAS). Anyone who has the URL can call the workflow, and URLs can be logged or leaked (in our experience: in tickets and chat messages).

Microsoft describes the alternative as keeping secrets, long-lived SAS URLs and access keys **out of workflows**: callers present a **Microsoft Entra ID token** instead, checked by **Easy Auth**.
</Step>

<Step id="what" name="What Easy Auth is">
**Easy Auth**, also called **App Service Authentication**, is a feature of the platform your Standard logic app runs on. When it's on, **every incoming HTTP request passes through it** before your app handles it.

It authenticates callers with an identity provider such as Microsoft Entra ID, validates their tokens, and passes identity information on in request headers. It needs no code: security is enforced **outside your workflow**.
</Step>

<Step id="checks" name="What it checks">
For a request with a token, Easy Auth checks the token's **audience** (`aud`) against your **allowed token audiences**. If they don't match, the caller gets **401 Unauthorized** before the workflow runs.

Two settings matter most:

- **Require authentication** rejects unauthenticated requests; **Allow unauthenticated** passes them through.
- By default it does **authentication, not authorization**: any user in your tenant could get a token. Use the **additional checks** to limit client applications, identities and tenants.
</Step>

<Step id="setup" name="Turning it on">
On the logic app, under **Settings** > **Authentication**, select **Add identity provider** and choose **Microsoft**. You create a new **app registration** or use an existing one.

Choose **single tenant** for supported account types. Microsoft warns against "Any Microsoft Entra directory - Multitenant" unless you have governance and Conditional Access in place. Easy Auth stores its configuration in app settings such as `WEBSITE_AUTH_ENABLED`; edit those only from templates.
</Step>

<Step id="request" name="For Request triggers">
Learn's security page confirms that a Standard workflow starting with the **Request** trigger (not a webhook trigger) can use Easy Auth for inbound calls, for example from a managed identity. For the steps, it links to a **Tech Community blog**, not a Learn article.

It also says Standard can use other authentication types **without disabling SAS**. Learn doesn't spell out how SAS and Easy Auth interact on the same trigger, so test both paths before you rely on it.
</Step>

<Step id="chat" name="For agent chat">
For **conversational agents**, Learn has a full walkthrough (preview). You need the **Application Developer** role in Entra ID and the **Azure Contributor** role or higher on the logic app: Microsoft notes that's not the same as Logic Apps Standard Contributor.

Learn recommends **Require authentication** (unless you plan to allow some endpoints) and a **302 redirect** for agents. After that, the portal's built-in chat page stops working; people use the external chat client URL instead.
</Step>

<Step id="mcp" name="For MCP servers">
MCP servers (preview) use **OAuth 2.0 by default**, which requires Easy Auth. Expose an API on the app registration; Learn recommends the scope **user_impersonation**, the default supported scope (another scope needs an override in `host.json`).

Set the allowed token audience to `api://<application-id-uri>/`, **with the trailing slash**. Unlike agent chat, Learn's MCP setup sets Restrict access to **Allow unauthenticated access**.
</Step>

<Step id="identity" name="Who called?">
When Easy Auth validates a request, it adds the caller's identity to the request headers, including normalized claims such as `X-MS-CLIENT-PRINCIPAL`, groups, roles and scopes.

Microsoft points out that downstream actions such as **Compose** or **Parse JSON** can then apply finer-grained authorization against those claims, for example (ours) only allowing a certain role to place large orders.
</Step>

<Step id="troubleshoot" name="When it says no" tag="TIP">
- **401** with `invalid_token` mentioning the audience: the token's audience doesn't match your allowed audiences (for MCP, check the trailing slash).
- **403** after authentication: Learn notes it might mean the workflow or agent wasn't found.
- With Require authentication on, it applies to **every** path of the app unless you exclude paths.
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- **Easy Auth** checks Entra ID tokens before requests reach your workflows.
- It validates the **audience**; add checks for apps, identities and tenants.
- Set it up under **Settings > Authentication** with a single-tenant app registration.
- Learn documents it fully for **agent chat** and **MCP**; for **Request triggers**, only briefly.
- Read the caller's claims from headers such as `X-MS-CLIENT-PRINCIPAL`.
</Step>
