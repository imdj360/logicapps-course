<Step id="problem" name="A database with no connector" tag="PROBLEM">
Your stock levels live in a **MySQL** database. There's no dedicated Logic Apps connector for it, and you don't want to build an API in front of it just to read a table.

If the database has a **JDBC driver**, a Standard logic app can talk to it directly.
</Step>

<Step id="what" name="The JDBC connector">
**JDBC** is a **built-in** connector, available **only in Standard**. You bring the database's JDBC driver (a set of JAR files) and the connector uses it, for any JDBC-supported relational database. It doesn't need the on-premises data gateway.
</Step>

<Step id="package" name="Add the driver">
Put the driver JARs in your project's `lib/builtinOperationSdks/JAR` folder, so they deploy with your workflows:

```text
MyLogicApp/
├── lib/builtinOperationSdks/JAR/
│   └── (driver .jar files)
├── StockSync/workflow.json
├── connections.json
└── host.json
```

Zip the project **contents** (no extra wrapper folder) and deploy, for example with `az logicapp deployment source config-zip`. In the portal you can instead upload them under **Artifacts** > **Assemblies** as **Client or SDK Assembly (Java)**.
</Step>

<Step id="connect" name="Connect">
A connection needs three values: the database **URL**, a **user** and a **password**. The URL format comes from your driver's documentation, not from Learn:

- **MySQL**: `jdbc:mysql://db-host:3306/stock`
- **Oracle**: `jdbc:oracle:thin:@//db-host:1521/ORDERS`, with Oracle's `ojdbc` driver

Keep the password in an app setting, not in the workflow (ours).
</Step>

<Step id="actions" name="Three actions">
The connector has **actions only**, so the workflow starts with another trigger, such as a schedule:

- **Execute query**: runs a query. Pass values through its **query parameters**, not by building the SQL text (ours).
- **Get tables**: lists the tables.
- **Get schema**: returns a table's schema.
</Step>

<Step id="alternatives" name="JDBC or a dedicated connector?">
Two databases also have their own built-in connector in Standard:

- **SQL Server**: adds **triggers** on changed rows and **managed identity**. Prefer it over JDBC (ours).
- **Oracle Database**: ready-made operations such as Get rows and Insert row, but in **public preview**. JDBC is the alternative if you want raw queries through a driver you control.
</Step>

<Step id="watch" name="Watch out" tag="TIP">
- The database must be **reachable from the logic app's runtime**: for a private database, use VNet integration or the hybrid model (ours, from Microsoft's Oracle guidance).
- Learn's JDBC page is short: no Java version, no URL examples, no preview/GA status. **Test** with your driver and database first.
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- **JDBC**: a Standard-only built-in connector for any database with a JDBC driver.
- Driver JARs go in `lib/builtinOperationSdks/JAR` and deploy with the project.
- Connect with **URL**, **user** and **password**; use **query parameters**.
- Prefer the **SQL Server** connector for SQL Server; Oracle can go either way.
</Step>
