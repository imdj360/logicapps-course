<Step id="problem" name="From JSON to decisions" tag="PROBLEM">
This order arrives at your Request trigger:

```json
{
  "orderId": "SO-1042",
  "customer": { "name": "Contoso Bikes", "email": null },
  "lines": [ { "sku": "WHEEL-26", "qty": 4 }, { "sku": "CHAIN-9", "qty": 2 } ]
}
```

You need the customer's name, a ship date three days from now, a one-line summary for the warehouse, and a fallback when the email is missing.

All of that is **expressions**: small formulas the runtime evaluates while the workflow runs. Every example below uses this order (the order is ours).
</Step>

<Step id="syntax" name="It starts with @">
An expression goes **anywhere in a JSON string value** and starts with `@`:

| You write | You get |
|---|---|
| `"@triggerBody()?['orderId']"` | `SO-1042` |
| `"@length(triggerBody()?['lines'])"` | `2` (a number) |

That's the **whole value** form: the string holds only the expression.
</Step>

<Step id="types" name="Expressions inside text">
To put an expression **inside other text**, wrap it in `@{...}`. That's **string interpolation**; Microsoft says inline expressions need the curly braces, and the result is always a **string**:

| You write | You get |
|---|---|
| `"Order @{triggerBody()?['orderId']} received"` | `Order SO-1042 received` |
| `"Ship by @{formatDateTime(addDays(utcNow(), 3), 'yyyy-MM-dd')}"` | `Ship by 2026-11-27` (if today is 2026-11-24) |
| `"@{length(triggerBody()?['lines'])}"` | `"2"` (a string, not a number) |

The last row is the catch. If a parameter `myAge` is 42, `"@parameters('myAge')"` returns the **number** 42, but `"@{parameters('myAge')}"` returns the **string** "42". Use the whole-value form when an action expects a number, an array or an object.
</Step>

<Step id="data" name="Reading data">
Most expressions start by reading something:

- `triggerBody()`: the trigger's body, shorthand for `trigger().outputs.body`.
- `body('Get_customer')`: an earlier action's body. `outputs('Get_customer')` returns all its outputs.
- `variables('total')` and `parameters('carrierUrl')`.
- `items('For_each_line')`: the current item in a For each loop.
</Step>

<Step id="null" name="When a field is missing" tag="FIX">
In our order the email is null. Ask for a property that isn't there at all, such as `triggerBody()['phone']`, and the expression can fail with the error **"Unable to process template language expressions"**.

Put a **`?`** before the property: `triggerBody()?['phone']`. If it's missing, the expression returns **null** instead of failing. Chain it for nested fields: `triggerBody()?['customer']?['email']`. Add a fallback with `coalesce`, which returns the first non-null value:

```json
"@coalesce(triggerBody()?['customer']?['email'], 'orders@example.com')"
```

Note that empty strings, arrays and objects aren't null, so `coalesce` keeps them.
</Step>

<Step id="functions" name="Functions inside functions">
Functions nest: the inner one runs first and feeds the outer one. Built up one step at a time for the ship date:

1. `utcNow()` → now, as a timestamp
2. `addDays(utcNow(), 3)` → three days later
3. `formatDateTime(addDays(utcNow(), 3), 'yyyy-MM-dd')` → `2026-11-27`

More with the same order:

| Goal | Expression | Result |
|---|---|---|
| Name in capitals | `toUpper(triggerBody()?['customer']?['name'])` | `CONTOSO BIKES` |
| First SKU | `first(triggerBody()?['lines'])?['sku']` | `WHEEL-26` |
| Bulk or normal | `if(greater(length(triggerBody()?['lines']), 5), 'bulk', 'normal')` | `normal` |
| Warehouse line | `concat(triggerBody()?['orderId'], ' / ', toUpper(triggerBody()?['customer']?['name']))` | `SO-1042 / CONTOSO BIKES` |

Other everyday functions: `split()`, `join()`, `guid()`, `equals()`, `and()`, `or()`, `empty()`, `last()`, `int()`, `string()` and `json()`.

Tip (ours): build a long expression in a **Compose** action first, run once, and check its output before you use it elsewhere.
</Step>

<Step id="gotchas" name="Small things that bite" tag="TIP">
- Wrap text values in **single quotes**: `length('Hello')`, not `length("Hello")`.
- A text value that really starts with `@` needs escaping as `@@`.
- `contains()` and `replace()` are **case-sensitive**; `startsWith()`, `endsWith()` and `indexOf()` aren't.
- Learn's workflow limits allow up to **8,192 characters** per expression.
</Step>

<Step id="params" name="Parameters and app settings">
For values that change per environment, use **parameters**, referenced with `@parameters('carrierUrl')`. Microsoft suggests parameters as the default way to parameterize values.

**App settings** hold global configuration for the logic app. For secure keys or strings, reference app settings from your parameters with `@appsetting('...')`, which is the only expression type allowed in `parameters.json`.
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- `@` alone keeps the value's type; `@{...}` puts an expression inside text and always returns a string.
- Functions nest; build long ones in a Compose action first.
- Read data with `triggerBody()`, `body()`, `outputs()`, `variables()`, `parameters()` and `items()`.
- Use `?['field']` to return null instead of failing, and `coalesce()` for a fallback.
- Single quotes for text, `@@` for a literal @, and watch case sensitivity.
- Use **parameters** for per-environment values, and reference **app settings** from them for secure keys.
</Step>
