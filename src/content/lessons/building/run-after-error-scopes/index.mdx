<Step id="problem" name="A step fails" tag="PROBLEM">
Your order workflow runs *Reserve stock*, *Charge card*, then *Confirm order*.

The card charge fails. Logic Apps marks it **Failed**, marks *Confirm order* **Skipped** (it never ran), and the whole run ends **Failed**. Nobody is told, and the reserved stock stays reserved.
</Step>

<Step id="idea" name="The idea: run after">
Every action has one rule: **"run me after the step before me…"**

- **Is successful**: the normal case, and the default.
- **Has failed**
- **Is skipped**
- **Has timed out**

That's all *run after* is. You change it in the action's **Settings**, and you must keep at least one ticked. (The first action after the trigger doesn't have it.)
</Step>

<Step id="single" name="React to one failure">
Add a **Notify team** action after *Charge card*, and set its run after to **Has failed** only.

- Card charged: *Notify team* is skipped, *Confirm order* runs.
- Card fails: *Notify team* runs, and the team hears about it.

This is the whole trick, on one action.
</Step>

<Step id="scope" name="Many actions? Use a box">
Doing that for every action gets messy. Instead, put the work in a **scope**: a box around several actions. The box gets **one status**: if any action inside fails, the box is **Failed**.

Put all the work, *Reserve stock*, *Charge card* and *Confirm order*, in a box called **Try**. After it, add a second scope, **Catch**, with run after set to **Has failed** and **Has timed out** on Try. Now one Catch watches all three actions: whichever fails, Catch runs.
</Step>

<Step id="result" name="Which step broke?">
Inside Catch you want to know *what* failed. `result('Try')` lists every action in the Try box with its **name**, **status** and **outputs**. Keep only the failed ones:

```json
"where": "@equals(item()['status'], 'Failed')"
```

Your alert can then say "*Charge card* failed: card declined". (`result()` only sees the top-level actions in the box.)
</Step>

<Step id="handled" name="Caught means Succeeded" tag="PROBLEM">
One surprise: once Catch handles the failure, the **run shows Succeeded**. The order failed, but your dashboard is green.

End Catch with **Terminate**, status **Failed**, and your own message. Now the run says what really happened. (Terminate can't go inside a For each or Until loop.)
</Step>

<Step id="monitor" name="Watch from outside" tag="TIP">
Run after handles one run at a time. To notice when failures **pile up**, add an alert in **Azure Monitor**, for example "when more than five runs fail in an hour".

With Terminate (Failed) in place, those runs end as Failed, so the alert sees them (ours).
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- **Run after** = "run me after the step before me succeeded / failed / was skipped / timed out".
- One action: set run after to **Has failed** to react.
- Many actions: wrap them in a **Try scope**; a **Catch scope** runs when Try fails.
- `result('Try')` tells you which action broke.
- A caught failure shows **Succeeded**: end with **Terminate (Failed)**.
</Step>
