<Step id="problem" name="Orders handled by hand" tag="PROBLEM">
Orders arrive from the website all day. An order clerk opens each one, types it into the ERP, and emails a reviewer whenever the total is above the review limit.

It's slow, it stops when the clerk is away, and a typo goes straight into the ERP.
</Step>

<Step id="idea" name="The idea">
**Azure Logic Apps is a cloud service for automating business processes and connecting systems, with little or no code.**

Think of the clerk's routine written down as a checklist, except the checklist starts itself when an order arrives and does the steps for you. Azure hosts, scales and monitors it.
</Step>

<Step id="trigger" name="It starts with a trigger">
That checklist is a **workflow**. Every workflow starts with **exactly one trigger**: the condition that must be met before anything else runs.

Here the trigger is **When an HTTP request is received**: the website sends each order to the workflow. Other triggers fire on a new email, a new file or a message in a queue, and many can also run on a schedule.
</Step>

<Step id="actions" name="Then come the actions">
After the trigger fires, **one or more actions** run in order. This is Microsoft's own example from the overview:

1. The trigger receives the order.
2. A **Condition** compares the order total with the review limit.
3. Under the limit: **Create order** in the ERP.
4. Over the limit: **Send an email (V2)** to a reviewer.

The trigger and every action are called **operations**.
</Step>

<Step id="connectors" name="Connectors do the talking">
Each operation comes from a **connector**. Azure Logic Apps has **1,400+ prebuilt connectors**, in two kinds:

- **Built-in** connectors run natively on the Logic Apps runtime, for faster performance. Here: the Request trigger, the Condition, and HTTP to the ERP.
- **Managed** connectors are Microsoft-managed proxies for a service's API, and most need an authenticated connection. Here: **Office 365 Outlook** for the email.

A later lesson compares the two kinds in detail.
</Step>

<Step id="definition" name="Designed visually, saved as JSON">
You build the workflow in the **designer**, in the Azure portal or Visual Studio Code. Underneath, every workflow has a **JSON definition** that you can also edit directly. In Standard it's a file named `workflow.json`.

For automated deployment, Azure Logic Apps supports **Azure Resource Manager templates**. The Security & delivery module covers that.
</Step>

<Step id="history" name="Consumption first, then Standard">
- **2016**: Azure Logic Apps became generally available on **July 27, 2016**, as a multitenant cloud service. That original model is what's now called **Consumption**.
- **2021**: Microsoft made **Logic Apps Standard** generally available on **May 25, 2021**, calling it "our new single-tenant offering".

Standard runs on a **redesigned single-tenant runtime**, hosted as an **extension on the Azure Functions runtime**. Per the Microsoft Learn docs, that design gives it portability and more performance. That's why Standard can run in Azure, in an App Service Environment v3, or on your own infrastructure.
</Step>

<Step id="resources" name="Standard or Consumption">
The workflow lives in a **logic app**, the Azure resource you create. There are two kinds:

- **Consumption**: one workflow per logic app, in shared multitenant Azure. Easiest to get started, and you pay per execution.
- **Standard**: many **stateful and stateless** workflows per logic app, on the single-tenant runtime with a hosting plan. It has more built-in connectors and integrated support for virtual networks and private endpoints.

**This course teaches Standard.** Consumption appears only as asides. The next lesson shows where a Standard logic app can run.
</Step>

<Step id="when" name="When to use it" tag="TIP">
Microsoft's own comparison of automation services:

- **Azure Logic Apps**: designer-first orchestration of business processes across services, systems, apps and data.
- **Azure Functions**: code-first orchestration with Durable Functions. The two can call each other.
- **Power Automate**: codeless automation for business users.
- **Azure Automation runbooks**: infrastructure tasks, such as restarting virtual machines.

One watch-out from day one: Logic Apps delivers each message **at least once**. Rarely, a message arrives twice, so steps that create things should be safe to repeat. The Reliability module shows how.
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- Azure Logic Apps automates business processes with little or no code.
- A **workflow** is one **trigger** followed by one or more **actions**.
- **Connectors** (1,400+) supply the operations: **built-in** run on the runtime; **managed** are Microsoft-hosted proxies.
- You design visually; the workflow is saved as **JSON**.
- **Consumption** came first (2016); **Standard** (2021) runs on a redesigned single-tenant runtime.
- **Standard** holds many workflows on a hosting plan. This course is Standard-first.
</Step>
