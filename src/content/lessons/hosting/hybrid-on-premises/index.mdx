<Step id="problem" name="The plant runs locally" tag="PROBLEM">
The factory's workflows talk to machines and systems on the plant network. The plant manager's rule: they must run **in the plant's own datacenter**.

Standard has a model for that: the **hybrid deployment model**. You still build a Standard logic app, but it runs on infrastructure you manage.
</Step>

<Step id="pieces" name="The pieces">
A hybrid deployment needs three things in the **same network**:

- An **Azure Arc-enabled Kubernetes cluster**, where the Logic Apps runtime runs in an **Azure Container Apps extension**.
- A **SQL database**, which stores run history, inputs and outputs.
- An **SMB file share**, which stores artifacts such as maps, schemas and assemblies.

The SQL database can be SQL Server, Azure SQL Database, Azure SQL Managed Instance or SQL Server enabled by Azure Arc.
</Step>

<Step id="where" name="Where it can run">
The cluster can be on-premises, in a private cloud or in a public cloud. Supported clusters include Azure Arc-enabled **AKS**, AKS on **Azure Local**, AKS on **Windows Server**, **Red Hat OpenShift** and **Rancher RKE2**.

The Azure side is currently available in a limited set of regions, including **West Europe**, **Sweden Central**, **UK South** and **East US**. Check the current list before you plan.
</Step>

<Step id="deploy" name="Deploying">
In the Azure portal or VS Code, you choose the **Hybrid** hosting plan and point it at your connected environment, the SQL connection string and the SMB share.

To deploy, **zip deployment** is the more stable and reliable option; Microsoft notes that SMB deployment is prone to 409 conflicts. Zip deployment needs a Microsoft Entra **app registration**. If you can't create one, SMB deployment still works. Both options depend on Azure management services.
</Step>

<Step id="scaling" name="Replicas, not instances">
Hybrid scales with **KEDA** and a Logic Apps scaler in your cluster. Instead of plan instances, you get **replicas**: by default at least **1** and at most **30**, configurable up to 1,000.

Each replica gets between **0.25 and 2 vCPU** (default 1) and between **0.1 and 4 GiB** of memory (default 2).
</Step>

<Step id="billing" name="Paying per vCPU">
You're responsible for your **Kubernetes infrastructure** and your **SQL Server licence**. Azure bills **vCPU usage**: allocated vCPUs × replicas × an hourly rate. **Managed connector** operations are billed on top.
</Step>

<Step id="auth" name="Connections need an app registration" tag="PROBLEM">
Managed API connections in hybrid **don't support managed identity**. You create your own **Microsoft Entra app registration** and give the logic app its details through the `WORKFLOWAPP_AAD_CLIENTID`, `WORKFLOWAPP_AAD_OBJECTID` and `WORKFLOWAPP_AAD_TENANTID` environment variables, with the client secret stored as a secret and referenced from `WORKFLOWAPP_AAD_CLIENTSECRET`.

This model needs connectivity to Microsoft Entra ID.
</Step>

<Step id="offline" name="When the link to Azure drops">
Hybrid isn't an air-gapped setup. It needs outbound connectivity for Azure Arc, Azure management and any managed connectors.

When the connection drops, the local runtime and workflows that use **only local dependencies** keep running. Managed connector operations need their Azure-hosted services, so they might be unavailable. The runtime can keep logging data for up to **24 hours**; beyond that you might lose it.
</Step>

<Step id="limits" name="What doesn't come along" tag="TIP">
Some Standard features aren't available in hybrid: **deployment slots**, **business process tracking**, **resource health** in the portal, and **managed identity** for connector operations.

And some function-based triggers, such as Blob, Cosmos DB or Event Hubs, need an `AzureWebJobsStorage` app setting with the connection string of the logic app's Azure storage account.
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- Hybrid runs the Standard runtime in a **Container Apps extension** on **Arc-enabled Kubernetes**, with a **SQL database** and an **SMB share**.
- It scales with **KEDA replicas** and bills **vCPU usage**; you run the cluster and SQL yourself.
- Managed connections use an **Entra app registration**, not managed identity.
- Workflows with only local dependencies can keep running offline; logs can be kept for up to **24 hours**.
- No deployment slots, business process tracking or managed identity for connectors.
</Step>
