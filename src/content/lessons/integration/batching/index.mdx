<Step id="problem" name="Too many small messages" tag="PROBLEM">
Orders arrive all day from the shop, the app and EDI partners: hundreds of single messages. The ERP team asks for something else: **one file per hour**, with all the orders in it.

Today each order goes on its own. Logic Apps has a pattern for collecting messages and releasing them together: **batching**.
</Step>

<Step id="pattern" name="Receiver and senders">
A batch needs two kinds of workflow:

- A **batch receiver** collects messages until your release criteria are met. It starts with the **Batch Operations** trigger, **Batch Trigger**.
- One or more **batch senders** send messages to it with the **Send to batch** action.

The receiver doesn't need to know anything about the senders, but each sender must know its receiver. Create the receiver first, in the **same subscription and region** as the senders.
</Step>

<Step id="release" name="When a batch is released">
The receiver releases a batch based on one or more criteria:

- **Message count**: after a number of messages.
- **Size**: after a total size in bytes.
- **Schedule**: on a recurrence, at least every **60 seconds**.

Select several to use them all. A batch holds at most **8,000 messages** and **80 MB**. Learn doesn't spell out how several criteria interact, so test your combination before you rely on it (ours).
</Step>

<Step id="sender" name="The sender's side">
In a Standard workflow, **Send to batch** takes the **batch name**, the **message content**, and the receiver's **workflow name** and **trigger name**.

The batch name is validated at run time and must match the receiver's. Change it on one side only, and the sender fails.
</Step>

<Step id="partitions" name="Partitions">
A sender can set an optional **partition name**, which splits the batch into logical subsets: for example one per warehouse, so each warehouse gets its own file. It can also set a **message ID**; if empty, a GUID is generated.

A partition holds at most **5,000 messages or 80 MB**. When it reaches either, the batch might be released even if your release criteria aren't met yet.
</Step>

<Step id="receive" name="Processing the batch">
When a batch is released, the receiver's run gets the messages as a collection called **Batched Items**. Process them with a **For each** loop; the designer adds one for you when an action works on single messages.

Inside the loop you can use the **Partition Name** and **Message ID** dynamic content, so you can group or trace them.
</Step>

<Step id="example" name="The hourly ERP file, end to end" tag="TIP">
Our design for the ERP request, using only the pieces above:

1. **Receiver** *Collect orders*: **Batch Trigger** with batch name `erp-orders`, released on a **Schedule** of every 1 hour.
2. **Senders**: the shop, app and EDI workflows each end with **Send to batch**: batch name `erp-orders`, the order as message content, and the receiver's workflow and trigger names. Each sets the **partition name** to its warehouse code, for example `WH-NORTH`.
3. **Each hour**, the receiver's run gets the **Batched Items** for a partition. A **For each** turns every order into a line, then a **Write file** step (for example an SFTP or Blob action, ours) writes **one file**, named with the **Partition Name**, such as `WH-NORTH-2026-11-24-14.csv`.

Result: one file per warehouse per hour, instead of hundreds of single orders. The names, file format and per-warehouse split are ours.
</Step>

<Step id="limits" name="What to know" tag="TIP">
- You can only see what's in a batch **after** it's released.
- The only way to release a batch early is to **change its release criteria** while it still holds messages. The new criteria then apply to the unsent messages.
- In Consumption, release criteria can also come from an integration account; in Standard you set them on the trigger.
</Step>

<Step id="recap" name="Recap" tag="RECAP">
- A **batch receiver** (Batch Trigger) collects; **batch senders** (Send to batch) send to it.
- Release by **message count**, **size** or **schedule** (min. 60 s); max 8,000 messages or 80 MB.
- The batch name must match on both sides, or the sender fails.
- **Partitions** split a batch into subsets of up to 5,000 messages or 80 MB.
- The receiver processes **Batched Items**, usually in a For each loop.
</Step>
